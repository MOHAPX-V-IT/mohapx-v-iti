# Сборка сайта из posts.json

Весь журнал собирается из одного файла — `posts.json` в корне репозитория.
Ты правишь только его, всё остальное GitHub собирает сам.

## Как добавить новый пост

1. Открой `posts.json`, найди массив `"posts"`.
2. Скопируй последний блок поста и вставь копию рядом. Поменяй в ней поля:

   - `"n"` — следующий номер по порядку (был 24, ставь 25).
   - `"rubric"` — одно из: `поле`, `разбор`, `мнение`, `инструмент`, `цифра`.
   - `"date"` — дата публикации в формате `ГГГГ-ММ-ДД`. Пост уйдёт в Telegram
     в этот день (если дата уже прошла, то при ближайшем запуске публикатора).
   - `"title"`, `"body"` — русский заголовок и текст. В тексте: пустая строка
     разделяет абзацы, `**жирный**`, обратные кавычки для `кода`, а строка
     `#рубрика` в самом конце — это хештег для Telegram.
   - `"title_en"`, `"body_en"` — то же на английском.

3. Сохрани, закоммить и запушь `posts.json`.

Дальше без тебя: GitHub пересоберёт страницу журнала, отдельную страницу поста,
обложки (русскую и английскую), `rss.xml` и `sitemap.xml`, закоммитит их обратно.
В свою дату публикатор отправит пост в канал.

## Что нельзя трогать вручную

Эти файлы собираются автоматически, правки в них затрутся при следующей сборке:
`journal.html`, `journal/post-*.html`, `journal/j*.jpg`, `rss.xml`, `sitemap.xml`,
`calculator.html`.

Правь только `posts.json`. Дизайн и общий стиль живут в `index.html`: если
меняешь его, шапка и стили автоматически проедут по всем страницам журнала.

## Запустить сборку вручную

Actions → «Пересборка сайта из posts.json» → Run workflow. Пригодится, если
хочешь пересобрать всё, не меняя `posts.json`.
